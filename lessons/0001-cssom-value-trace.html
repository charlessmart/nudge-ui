2. The browser has two useful views

Given:

:root {
  --space-4: 1rem;
}

.card {
  padding: var(--space-4);
}
ViewLikely answerWhy the inspector needs it
CSSOM rule.card + padding: var(--space-4)Finds authored declarations and cascade evidence.
Token resolver--space-4 → 1remShows the meaningful project token.
Computed styleOften 16pxConfirms what the browser actually paints.

3. Follow the repository path

  1. resolution.ts walks document.styleSheets and cssRules.
  2. resolveTokenValue() follows var(), aliases, fallbacks, and modifiers.
  3. resolveDeclaration() expands safe shorthands into rows such as padding-top.
  4. InspectorShell.tsx passes those rows to the style editors.
  5. TokenField.tsx chooses between a token chip and authored raw input.
  6. managedStylesheet.ts applies edits as rules, never inline styles.

Why does the runtime resolver also scan the text of same-document <style> elements?
