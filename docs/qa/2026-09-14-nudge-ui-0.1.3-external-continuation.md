## Executive summary

The external packed-consumer sweep is now green for the current representative matrix. The earlier Nudge-owned failures have either been fixed by the candidate PRs listed below or were proven to be stale generated output and fixture/environment problems. A fresh clean pack also passes the package verifier and fresh browser smoke checks in the most sensitive Vite, Next.js, and Astro cases.

The most important change since the previous report is that the Next.js token-catalog failure no longer reproduces. A fresh Next Milosh run now opens Settings > Tokens and displays the catalog, including `--accent`, color variables, spacing variables, radius, and other variables. The earlier empty catalog was produced by the old package/build state and should remain in the report only as historical failure evidence.

No current browser run in the expanded matrix produced a Nudge-owned runtime error. The remaining failures are environmental or fixture-specific:

- Google Fonts requests prevent production builds in repositories that fetch fonts at build time while offline.
- An Astro fixture requires the native `sharp` install script to build statically.
- The local machine runs Node.js `20.20.1`, while the repository recommends Node.js `22.12` or newer.
- Third-party semantic-instrumentation skips and fixture console warnings remain expected and do not indicate an inspector failure.

The clean package artifacts are suitable for continued release review after the open fix PRs are merged. This QA run did not publish to NPM.

## Scope and method

This pass used disposable clones and local package tarballs. Each package build was regenerated before the final run, then installed into the external repositories with the exact local artifacts. The browser checks used Chromium and trusted pointer interaction at a 1280 × 720 preview size where the inspector was embedded.

For each host, the workflow covered as much of the following as the repository exposed:

1. Install the packed consumer dependencies.
2. Start the host's development server and confirm the application renders.
3. Confirm the inspector bootstrap and panel load.
4. Select elements and verify source identity.
5. Inspect component information and typed props where the host exposed them.
6. Open the token catalog and edit a token.
7. Edit a regular, non-token style.
8. Edit inline text.
9. Open Canvas and drag a preview element.
10. Capture browser and console evidence, classifying host warnings separately from Nudge errors.

The final clean source candidate was assembled in disposable worktree `/private/tmp/nudge-final-pack-source` from `origin/main`, with the reviewed fix commits applied in order. `pnpm run build:packages` completed successfully. `node scripts/verify-packages.mjs` verified all ten publishable packages at version `0.1.3` in `/private/tmp/nudge-qa-final-clean-pack-20260914`.

The ten verified artifacts were:

`create-nudge-ui`, `nudge-ui-agent-protocol`, `nudge-ui-astro`, `nudge-ui-compiler`, `nudge-ui-css`, `nudge-ui-inspector`, `nudge-ui-mcp`, `nudge-ui-nextjs`, `nudge-ui-standalone`, and `nudge-ui-vite-react`.

The external repositories were disposable. No upstream repository was changed.

## Findings and disposition

### Resolved: Vite component-runtime identity and invalid hooks

The original Hayyi failure was caused by a Nudge-owned component runtime boundary. The inspector's component semantics could load a second React identity or otherwise invoke hooks against the wrong runtime. The Vite adapter now prebundles and resolves the package-owned component runtime consistently.

Evidence:

- Clean-pack Hayyi smoke has no invalid-hook errors.
- The full Hayyi workflow reaches selection, token editing, regular styles, inline text, and Canvas.
- The Ethanzs and Charan Vite cases also load the inspector without the previous runtime failure.

Fix PR: [#36](https://github.com/charlessmart/nudge-ui/pull/36).

### Resolved: Next/Turbopack runtime aliases

The earlier Okeken failure occurred when the generated Next adapter emitted an absolute package-store path for `@nudge-ui/inspector/component-runtime`. Turbopack does not support that server-relative import form in this boundary. The Next adapter now uses the package-owned runtime seam without asking Turbopack to resolve the unsupported absolute alias.

Evidence:

- The no-Nudge Okeken control was clean, isolating the old failure to the Nudge integration.
- The current Okeken run renders the app and completes the browser workflow.
- The current Milosh and Xantorres runs also load under Turbopack.

Fix PR: [#41](https://github.com/charlessmart/nudge-ui/pull/41).

### Resolved: Next workspace token inventory

Next applications can keep their token declarations in a sibling workspace package rather than in the app's immediate source tree. The token inventory now uses the adapter's sidecar and workspace evidence to discover those declarations instead of stopping at the app directory.

Evidence:

- Okeken exposes the sibling-workspace catalog.
- Milosh's fresh catalog contains 26 variables, including `--accent`.
- Token edits remain live in the preview.

Fix PR: [#42](https://github.com/charlessmart/nudge-ui/pull/42).

### Resolved: layered token preview precedence

The managed token projection no longer retains an authored `layer` wrapper that can cause a normal controller declaration to lose to an authored normal declaration under cascade-layer ordering. Token edits therefore apply predictably in layered design systems.

Fix PR: [#49](https://github.com/charlessmart/nudge-ui/pull/49).

### Resolved: Next server bootstrap and stale Turbopack output

The Next adapter now injects the client module from the root layout at the server boundary. This avoids the client-boundary hydration problem in the supported Next setup. The remaining historical Milosh script warning was then traced to stale `.next` output rather than current package code.

Fix PR: [#50](https://github.com/charlessmart/nudge-ui/pull/50).

### Resolved: hidden duplicate inline text targets

The inline text target collection now excludes hidden and duplicate text nodes. This prevents the editor from selecting an invisible or stale copy when frameworks generate parallel markup.

Fix PR: [#48](https://github.com/charlessmart/nudge-ui/pull/48).

### Resolved: managed stylesheet serialization and CSSOM reparse

The inspector keeps a canonical in-memory managed stylesheet and serializes the complete projection whenever it changes. This prevents a development server or CSSOM observer from reparsing a partial style node and losing earlier edits. The implementation is covered by the focused managed-stylesheet tests and was rechecked with the packed Astro Tatooles consumer.

Fix PR: [#51](https://github.com/charlessmart/nudge-ui/pull/51).

### Not a current Nudge failure: initializer callback form

The Hayyi Vite configuration uses callback-form `defineConfig`. The initializer implementation and its unit tests explicitly cover callback, spread, and computed Vite configurations. The disposable fixture already uses the supported direct `nudgeUi()` API. No fresh callback-form failure was found, so no additional patch was raised for this item.

### Not a current Nudge failure: raw-style probes on wrong or cascaded targets

The prior Ethanzs and Astro-free raw-style observations were not reliable defects. In both cases the initial probe measured a target that did not own the declaration being changed or whose computed value was affected by a cascade/target mismatch. Focused probes on owned targets passed in Hayyi, Ethanzs, Charan, Milosh, Xantorres, and the Astro cases.

The remaining recommendation is to retain explicit regression coverage for target ownership and computed-style verification. This is a test-hardening opportunity, not an observed release-blocking failure in the current external matrix.
