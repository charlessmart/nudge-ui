# 0041 — Active package CSS token catalog

**Labels:** enhancement, needs-triage
**Type:** AFK
**Milestone:** Token inventory and CSS-value fidelity

## User story

As a consumer whose app imports a published design-system stylesheet, I get a
complete token catalog without manually naming the package or configuring an
external token source.

## Current behaviour

The eager CSS scan deliberately skips `node_modules`. Newvato imports the
published `@envato/design-system` theme through its application stylesheet, so
the browser can resolve a selected `var(--color-content-primary)` through
CSSOM, but the plugin catalog does not initially contain its peer declarations.
The picker therefore has no complete input catalog to offer as alternatives.

## Desired behaviour

Build an active-stylesheet discovery seam for the plugin. It follows the CSS
import graph that Vite resolves for the host application's loaded stylesheets
and contributes custom-property declarations from those resolved files to the
normal virtual token catalog. Package-origin entries retain package provenance
and source information, while project-origin entries preserve their existing
behaviour.

Discovery is deliberately bounded by the active stylesheet graph. It must not
recursively crawl all of `node_modules`, and it must not require consumers to
declare every design-system package manually. An explicit source option may be
provided only for runtime-injected or otherwise unresolvable stylesheets; it is
an escape hatch, not the standard installation path.

## Acceptance criteria

- [x] A CSS import from an installed package contributes its custom-property
      declarations to the dev virtual token catalog before the inspector first
      needs them.
- [x] Nested imports and package CSS resolved by Vite are followed only when
      reachable from an active host stylesheet.
- [x] Package token entries expose stable source and package provenance without
      being mislabelled as editable project declarations.
- [x] HMR updates or removes catalog entries when an active host stylesheet or
      a reachable imported stylesheet changes.
- [x] The implementation never performs a broad recursive `node_modules`
      scan; unrelated installed package CSS is absent from the catalog.
- [x] A focused package-CSS fixture proves that a catalog containing
      `--color-content-primary` also contains its peer content-color tokens,
      plus `--spacing-*` and `--border-radius-*` examples.
- [x] Unit tests cover import-graph discovery, provenance, duplicates, and
      unreadable/missing imports; Playwright covers first inspector load with
      the package fixture.
- [x] Dev-only gating remains intact: production virtual token modules remain
      empty and production bundles contain no inspector instrumentation.
- [x] `pnpm lint`, `pnpm typecheck`, relevant Vitest and Playwright suites,
      and `pnpm --filter sandbox build` pass.

## Out of scope

- Selecting, grouping, or ranking candidates in the inspector UI (#0040).
- Recursively indexing every installed package.
- Importing TypeScript theme-contract modules (#0042).
- Editing third-party package CSS.
