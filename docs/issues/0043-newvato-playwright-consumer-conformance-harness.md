# 0043 — Newvato Playwright consumer-conformance harness

**Labels:** enhancement, needs-triage
**Type:** AFK
**Milestone:** Token inventory and CSS-value fidelity

## User story

As a maintainer of Design Tool, I can run meaningful end-to-end Newvato
coverage locally without driving an authenticated browser session by hand.

## Current behaviour

Newvato can opt into the local Design Tool packages in development, but testing
token behaviour requires a maintainer to run the application and operate the
inspector manually. Its ordinary browser suite targets an authenticated hosted
environment, which is neither deterministic nor suitable for a fast Design
Tool feedback loop.

## Desired behaviour

Create an opt-in local consumer-conformance lane. Newvato exposes a
development-and-E2E-only, no-auth fixture route that imports its real root CSS
and renders real `@envato/design-system` primitives representing colour,
spacing, radius, typography, and Sprinkles-backed token usage. Its normal
application route, production output, and authentication flow remain
unchanged.

The Design Tool repository owns a Playwright project that starts only
Newvato's web application with `VITE_DESIGN_TOOL=true` and an explicit E2E
fixture flag on a disposable localhost port. It verifies the inspector through
its public browser behaviour and Shadow-DOM UI, using the local linked Design
Tool packages. A small local configuration/command discovers the Newvato
checkout, checks that its package links point to this workspace, and skips with
an actionable message when the private checkout or dependencies are absent.

## Acceptance criteria

- [x] Newvato has a stable no-auth fixture route that is reachable only under
      an explicit development/E2E flag and imports the real published design
      system CSS used by the app.
- [x] The fixture contains stable test targets for Content Primary/Secondary,
      spacing, border radius, typography, and a Sprinkles-generated class.
- [x] Design Tool's Playwright configuration starts Newvato's web app only;
      it does not require Rails, Caddy, Foreman, SSO, or an existing browser
      profile.
- [x] One command runs the local consumer suite when a configured Newvato
      checkout is available, and reports a clear skip/setup diagnosis when it
      is not.
- [x] The suite selects a real fixture element, observes its resolved current
      token, opens the applicable picker, and sees compatible peer tokens.
- [x] The suite selects a peer token and proves the rendered computed style
      changes through the managed stylesheet without adding an inline `style`
      attribute to the target element.
- [x] Tests cover the same flow for colour, spacing, radius, typography, and
      the Sprinkles fixture. Contract-path assertions are conditional on
      optional contract enrichment being configured.
- [x] Public CI remains independent of the private Newvato checkout. A
      package-style public fixture provides deterministic equivalent coverage;
      Newvato is an opt-in local conformance lane.
- [x] Newvato's ordinary dev and production behaviour is unchanged when the
      E2E flag is absent.
- [x] Both repositories' relevant lint, typecheck, unit, Playwright, and
      production-build checks pass without weakening the Design Tool dev-only
      contract.

## Out of scope

- Automating a real authenticated Newvato user journey.
- Making the private Newvato checkout or package credentials a public CI
      dependency.
- Replacing Newvato's existing application-owned test suite.
- Token discovery, compatibility, and contract-enrichment implementation.
