# 0022 — Global tokens tab with theme-aware editing

**Labels:** enhancement, needs-triage
**Type:** HITL
**Milestone:** 2 — Core loop

## User story

As a designer, I can switch the inspector from its element-focused Inspect tab
to a Tokens tab, find any project design token, and preview an edit to the
token's active-theme declaration across the entire rendered site. For example,
changing `--primary-text` updates every element that consumes that custom
property without creating individual element overrides.

## Current behavior

The inspector edits styles for one selected source site or rendered instance.
It can resolve and substitute tokens used by that element, but it has no
surface for browsing or editing the global token catalog.

The build-time virtual module already exposes a contextual token catalog. A
token has one identity and can retain multiple declarations with source,
selector, media, supports, scope and layer context. The current token field,
however, owns element-specific write actions, and the canonical change model
assumes every change targets an instrumented element.

The existing component named `ColorPicker` displays a swatch and text/token
field but does not provide an interactive color picker.

## Desired behavior

### Inspector tabs

Add top-level `Inspect` and `Tokens` tabs to the inspector panel. `Inspect`
remains the default and retains the current element-selection and override
workflow. `Tokens` is usable without selecting an element and is dedicated to
global design-token edits.

### Catalog, search and grouping

The Tokens tab lists project-authored global tokens from the contextual token
catalog: `:root` variants, `@theme`, and supported global layer/scope
declarations. It does not include component-local custom properties,
inspector-owned `--dt-*` variables, transient runtime variables, or dependency
tokens from `node_modules`.

Provide case-insensitive search across token names and authored values. Group
tokens as Color, Spacing, Typography, Radius, Shadow and Other using token names
and parseable values, then sort alphabetically within each group. No grouping
configuration is required in this slice.

Render one primary row per token. The row shows the token name, its active
authored value, its currently resolved value when that differs, and its source
location. An expandable Variants section lists all other declarations with
their values and selector/media/supports/scope/layer context as read-only
information.

### Active theme and contextual declarations

Only the declaration winning in the host page's current context is editable.
Active-declaration resolution must respect applicable root selectors/classes/
attributes, media queries including `prefers-color-scheme`, supports rules,
scopes, layers, importance and source order. The value painted by the browser
is the runtime source of truth; the build-time catalog supplies inventory,
authored values and source attribution.

Re-evaluate the active declaration when relevant host root attributes/classes
or media-query matches change. The inspector follows the host site's theme; it
does not add a control for changing the host theme.

A token with no declaration active in the current context remains visible and
is labelled `Inactive in current theme`. Its variants are visible, but editing
is disabled until one declaration becomes active. Never guess which inactive
variant the user intended to edit.

### Shared token-field interaction

Refactor the token field into reusable controlled UI with write behavior
supplied by its consumer. Preserve the existing element-edit behavior through
an element-specific adapter; do not duplicate the token picker/autocomplete
interaction for the Tokens tab.

For a global token definition:

- Selecting another compatible token writes an alias such as
  `--primary-text: var(--gray-900)` for the active declaration.
- Unlinking an alias changes the field to free text, initially populated with
  its resolved value.
- Free-text input offers compatible token suggestions and can be promoted back
  to an alias.
- Suggestions exclude the token itself and any alias that would introduce a
  direct or transitive cycle.
- Empty values are not committed. A requested value that does not paint is
  retained as a preview conflict rather than reported as successful.
- Free text commits on Enter or blur; Escape restores the current committed
  value.

Color-classified fields always show a swatch, whether the value is token-backed
or free text. The swatch resolves aliases and previews valid color text while
the user types. Clicking it opens the native browser color control; choosing a
color supplies a literal value through the same controlled edit path. This
behavior also extends to existing raw color fields in the Inspect tab. A custom
saturation/hue/alpha picker is deferred.

### Global preview, history and handoff

Token edits are session-only previews. They do not rewrite source files.
Project each edit into the single managed stylesheet using the active
declaration's selector and enclosing conditional context so the override does
not leak into inactive themes. Never write an inline style. Editing a token
must immediately update every current consumer on the page and survive React
re-renders.

Represent token changes as first-class global targets in the canonical change
set rather than fabricating element identity. A token change is keyed by token
identity plus declaration source/context and stores its original authored
value, current requested value and preview result. Repeated edits collapse to
one baseline-to-current delta. Returning to the baseline removes the delta.
Undo, redo, single-change revert and clear changes rebuild the same managed
stylesheet projection used by element edits.

Changes and copied prompts show global token edits separately from element
overrides. Each entry includes the CSS custom-property name, active theme/
conditional context, source file and line, and original → requested authored
value. Prompt output includes the custom-property name and contextual selector
as grep/selector fallbacks and does not imply that a token edit belongs to a
selected React element.

### Architecture decision

Write a new ADR and add it to the ADR index. It must preserve ADR-0003's single
managed stylesheet, no-inline-style rule, pure history projection and stable
`data-*` targeting for element edits, while allowing contextual selectors and
conditional wrappers specifically for global token-definition previews.
Existing ADRs remain immutable.

## Key interfaces and contracts

- Contextual token declaration identity must be stable enough to distinguish
  declarations of the same custom property in different sources or contexts
  and to determine their cascade order.
- The shared token field is controlled: its display/edit state is independent
  of whether the consumer writes an element property or a global token
  declaration.
- The canonical change model distinguishes element targets from global-token
  targets. Token changes do not require `cid`, element source identity or
  instance evidence.
- Managed stylesheet rules can preserve selector plus media, supports, scope
  and layer context for a global-token override.
- Preview verification reports requested value, computed/resolved value and an
  applied/conflict result for global token edits.

## Acceptance criteria

- [ ] The inspector has `Inspect` and `Tokens` tabs; Inspect remains the default
      and Tokens works without an element selection
- [ ] The Tokens tab lists only project-authored global catalog tokens and
      provides case-insensitive search
- [ ] Tokens are grouped into Color, Spacing, Typography, Radius, Shadow and
      Other and sorted alphabetically within each group
- [ ] Each token row shows name, active authored value, resolved value when
      different, source, and expandable read-only declaration variants
- [ ] Active-declaration resolution respects selectors, media, supports,
      scopes, layers, importance and source order, and follows host theme changes
- [ ] Tokens with no active declaration remain visible, are labelled inactive,
      and cannot be edited
- [ ] Editing affects only the active declaration context and updates all token
      consumers live without leaking into inactive theme variants
- [ ] The existing token field interaction is reused through a controlled
      contract for both element-property and global-token edits
- [ ] Selecting a token creates an alias; unlinking enables free text; token
      autocomplete can promote free text back to an alias
- [ ] Self-referential and transitively cyclic token aliases cannot be selected
- [ ] Color fields always show a live swatch for token-backed and raw values;
      clicking it opens a native color control
- [ ] Free-text commits on Enter/blur, cancels on Escape, and empty input is not
      committed
- [ ] Global token edits are first-class canonical changes with correct
      baseline deduplication, undo, redo, revert and clear behavior
- [ ] The managed stylesheet remains the only preview write surface; token
      rules preserve active contextual wrappers and no inline styles are used
- [ ] Preview verification reports applied/conflict honestly and retains
      conflicted requested changes for handoff
- [ ] Changes and copied prompts identify global token, active context,
      source location and authored before/after values with grep-ready fallback
- [ ] A new ADR records the global-token exception to element identity selectors
      and the ADR index is updated without modifying prior ADRs
- [ ] Unit tests cover grouping/search, active/inactive context resolution,
      aliases/cycles, controlled token-field behavior, color swatch/picker,
      managed contextual rules, canonical history and prompt output
- [ ] Playwright coverage edits a light/dark token, verifies every consumer
      updates, switches the host theme, and proves the inactive variant was not
      overwritten
- [ ] `pnpm --filter sandbox build` succeeds and the production bundle contains
      no inspector UI, managed token overrides or token metadata
- [ ] `pnpm lint`, `pnpm typecheck`, relevant Vitest suites and relevant
      Playwright suites pass

## Out of scope

- Directly rewriting CSS or framework token source files
- Editing inactive theme variants from the current host context
- A Tokens-tab control for switching the host site's theme
- A custom saturation/hue/alpha color picker
- User-configurable token grouping or taxonomy
- Component-local, runtime-generated, dependency or cross-origin token discovery
- Adding, renaming or deleting token definitions
- Persisting previews across reloads or synchronising them across tabs
