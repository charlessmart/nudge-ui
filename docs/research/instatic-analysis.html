1.3 CSS Substitution Encoding — The var()/env() Problem

This is one of the most clever engineering decisions in the codebase. It solves a fundamental browser CSSOM inconsistency.

The Problem

When CSS contains var() or env(), browsers disagree about what the CSSOM exposes:

  • Chromium: stores a "pending-substitution value" — style.length enumerates longhands but getPropertyValue() returns ""
  • happy-dom (test env): destroys the declaration entirely — border-left: 1px solid var(--rule) becomes three longhands each reporting only var(--rule) (the 1px solid part is gone)

The Fix

Rewrite before parsing — declarations with var( / env( are rewritten to marker custom properties:

/* Original */
border-left: 1px solid var(--rule)

/* Rewritten before CSSOM parse */
--instatic-sub-border-left: 1px solid var(--rule)

Every CSS engine preserves custom property declarations verbatim. After parsing, decodeSubstitutionProperty(kebab) strips the --instatic-sub- prefix back to the real property name.

Substitution Encode/Decode Pipeline Raw CSS ──► encodeSubstitutionDeclarations(css) ──► CSSStyleSheet.replaceSync() ──► walk CSSOM ──► readCssDeclarationBlock() ──► NewStyleRule ↑ Rewrites to --instatic-sub-* props ↑ decodeSubstitutionProperty() strips prefix back src/core/css-substitution/index.ts

The scanner is a character-by-character state machine (not regex) that tracks:

  • String quotes (single/double)
  • Comment depth (/* ... */)
  • Parenthesis and bracket nesting
  • @keyframes and @font-face blocks that must NOT be encoded

1.6 Edge Cases & Reliability

Well-Handled

  • var()/env() byte-faithful preservation via substitution encoding
  • Duplicate classes within one file → later wins, warning emitted
  • Cross-sheet conflicting class defs → surfaced as conflict in wizard
  • Path traversal attacks → rejected during ingest
  • ZIP bomb detection → 5GB uncompressed guard
  • Per-rule resilience → individual failures caught, processing continues
  • Google Fonts → parsed from @import, installed as self-hosted
  • @font-face external-only → external-font warning, skipped
  • CSS @import cycle detection → stack-based with warning
  • Background url() normalization → canonical url('payload')
  • Bare text node synthesis → <div>98%</div> imports faithfully
  • Internal link rewriting → club.html → cms:page:<id>
  • CDN import rewriting → esm.sh/jsdelivr → npm specifier → self-hosted

Limitations / Risks

  • Substitution scanner is hand-rolled — tracks quotes/comments/parens but does not deeply understand CSS grammar
  • @container detection uses structural cssText.startsWith('@container') heuristic — could miss unusual formatting
  • Color token extraction only from root-scope ambient rules, non-!important
  • Font stack parser is manual character-by-character with quote tracking
  • Property allowlist is permissive — accepts any syntactically-valid CSS property name
  • </style neutralization doesn't run on kept-mode stylesheets (those pass through user's original source)
  • Bootstrap exempt patterns are hardcoded — non-Bootstrap utility frameworks would not benefit
  • Keyword matching for color token extraction uses a hardcoded list — CSS Color Level 4 additions may not be recognized

1.7 Publisher CSS Output Pipeline

Published CSS Bundle System src/core/publisher/siteCssBundle.ts Published pages get 4 separate CSS files: 1. reset.<hash>.css — constant reset across all projects 2. framework.<hash>.css — @font-face + framework vars + utilities 3. style.<hash>.css — user-authored class registry 4. userStyles.<hash>.css — user-authored global stylesheets (SiteFiles) Tree-shaking: only class-ids referenced by page nodes are emitted. Ambient rules are always included (they match by CSS selection, not node assignment). Emission Order (for @media sorting): Base declarations ──► Custom conditions (@container, @supports) ──► Viewport contexts sorted: max-width widest first min-width narrowest first other (registry order)

2.2 Why Iframes? (Not Scaled <div>s)

Most visual editors (Webflow, older Framer) render a single <div> with transform: scale() or a max-width wrapper and fake viewport sizes with CSS. Instatic chose real iframes per breakpoint for three structural reasons documented at IframeFrameSurface.tsx:1-26:

Problem with DivsIframe Solution
<body> is the editor chrome — user CSS like body { background: black } paints the entire editor Each iframe gets its own real <body>. User CSS is fully isolated.
Wrapper Divs between authored elements — CSS combinators (>, +, ~, :nth-child()) see wrapper divs, not authored elements Modules spread handlers directly onto their root element. Zero wrapper elements between authored siblings. Combinators work identically to production.
Faked viewport — vw/vh units, media queries, and scroll behavior don't match published page Each iframe is sized to the exact breakpoint width. Media queries, viewport units, and scroll behavior match production perfectly.
Style leakage — editor chrome CSS bleeds into the preview; user CSS bleeds into the editor Complete style isolation between frames. Plus a deliberate unlayered-vs-@layer cascade split (see below).

2.5 Performance Optimizations

Pan/Zoom — Ref-Based, GPU-Composited

  • transformRef mutates the DOM element directly via el.style.setProperty() — zero React renders at 60fps
  • Only CSS transform changes — GPU-composited, no layout/paint
  • RAF-batched DOM writes coalesce gesture events
  • Zustand store updated 100ms debounced after interaction ends
  • External sync (toolbar buttons, +/- keys) guarded by deep-equality check

Selection Overlays — Lazy RAF Loop

  • Rings are position:absolute overlays outside the transform layer
  • 1px borders are box-shadow — stays exactly 1px at every zoom
  • RAF loop only runs when hasOverlayWork is true — no ring, no loop
  • Each tick: READ phase (snapshot shared geometry) → WRITE phase (only when rect changed)
  • Zero per-frame querySelector scans — uses cached element lookup

Iframe Auto-Height — Feedback Loop Guard

useIframeFrameAutoHeight.ts:37-63: Frames grow to content height (no inner scrollbar). Body gets min-height: 800px artboard floor. A feedback loop guard caps self-driven resizes at 60 cycles and resets on external mutations. When replacing long→short pages, stale scroll height is ignored.

Frame Collapsing

Collapsed breakpoint frames keep a slim header label but drop the entire heavy iframe (DOM removed). State is ephemeral editor-session — not persisted. Reload clears collapsed state. canvasSlice.ts:78

Cross-iframe Event Bridging

2.6 Live Mode (Editable Preview)

Live Mode: Fully Editable Single-Frame View CanvasLiveSurface └── IframeFrameSurface (interaction='live') ├── Fluid width (fills space) ├── Breakpoint presets clamp to min(breakpoint.width, containerWidth) ├── Side drag handles resize between 240px and breakpoint width ├── Symmetric drag: 1px pointer travel = 2px width change ├── Live width badge: "{N}px" ├── Native scroll (not pan) ├── No wheel/keyboard forwarding to parent ├── Canvas chrome CSS NOT applied (cursor, user-select, outline overrides) └── Form controls LIVE (not suppressed)

The live view reuses the exact same IframeFrameSurface, NodeRenderer, and selection overlay system. Only the wrapping layout and event handling differ. This means:

  • You can edit text, drag elements, modify styles while in "live" mode
  • No separate code path for rendering read-only content — it's the same renderer
  • Interactions feel native because the iframe scrolls normally, form elements work, etc.

3.4 Performance Strategy

No virtualization. Instatic does not use react-window, react-virtuoso, or any virtual list. Instead, it relies on precise granular subscriptions and React.memo:

TechniqueHowImpact
React.memo TreeNode.tsx:66 — re-renders only when nodeId or depth change Base optimization — props equality = no re-render
Per-node Zustand selectors Each TreeNode subscribes to only its own isSelected and isHovered booleans Canvas selection → only 2 rows re-render (old + new), not all 1,000+ rows
useSyncExternalStore for expansion Extension state lives in an external ExpansionStore class — not React state, not Zustand. A single toggle fires a targeted notify() that only triggers the 1 toggled row's subscription. Expanding a row doesn't recreate a context value that re-renders every TreeNode
Stable child arrays EMPTY_CHILDREN const prevents referential inequality Avoids unnecessary re-renders on empty children
Per-node class subscriptions TreeNode subscribes to site.styleRules — renaming a class updates every referencing node Granular via Mutative copy-on-write in Zustand
Search bypasses tree When search active, renders a flat SearchResults list — not recursive TreeNode No recursive rendering during search; O(n) flatten + filter
Single-slot memo for active page selectActivePage uses a single-slot cache (_activePageCache) so O(pages) scan runs once per store update, not once per subscriber All subscribers share one computation store.ts:178-191

Key Insight The ExpansionStore pattern (expansionStore.ts) is particularly elegant. Instead of putting expand/collapse state in React or Zustand (which would re-render every consumer on every toggle), it lives in an external observable class. Only the toggled row subscribes via useSyncExternalStore, and only that row re-renders.

4. Takeaways for Nudge UI

Import / Style Parsing

Instatic ApproachRelevance to Nudge UI
Substitution encoding for var()/env() — rewrite to marker custom props before CSSOM parse Adopt If you parse user CSS at any point, this technique is essential for reliability. The CSSOM is fundamentally broken for var(). The character-by-character scanner with comment/string/paren tracking is a proven pattern.
NewStyleRule internal shape — unified camelCase props bag with contextStyles for @media/@container/@supports Consider The unified contextStyles map is cleaner than separate @media/@container/@supports representations. The class vs ambient distinction elegantly handles both utility-class-first workflows and freeform CSS.
Declarative element mapping rules with ordered match + conditional recursion Adopt The HTML_TO_MODULE_RULES table pattern is cleaner than imperative mapping logic. The hasElementChild conditional (text vs container) is a neat solution for ambiguous elements like headings.
Canonical CSS sanitizer — single dependency-free module for value/name/url checks Adopt A single sanitization authority prevents inconsistencies. The </style → <\/style trick is defense-in-depth worth implementing.
4-file CSS bundle (reset + framework + styles + userStyles) with proper hashing Consider Caching strategy with content-hash filenames. Tree-shaking class-ids by page usage.

Canvas / Preview

Instatic ApproachRelevance to Nudge UI
Real iframes per breakpoint (not scaled divs) Consider If you need CSS combinators, true <body>, and working media queries, iframes are the answer. The cost is cross-iframe event bridging complexity. Evaluate whether your use case needs combinator/body fidelity vs simpler div-scale approach.
Design + Live both editable (Preview is separate modal) Adopt pattern Having design and "preview-like" editable mode share the same renderer is elegant. Then a truly read-only preview is a separate build-and-display step.
Unlayered vs @layer cascade — editor chrome always wins Adopt This is an elegant CSS-native solution to prevent user CSS from breaking editor chrome. No specificity arms race needed. One extra <style> element unlayered, everything else in @layer user-authored.
previewFrame: boolean — breakpoints can be style targets without spawning iframes Adopt Users can add arbitrary responsive contexts (style target only) without cluttering the canvas with more iframes.
Ref-based pan/zoom — GPU-composited, zero React re-renders at 60fps Adopt The pattern of direct DOM mutation during gestures + debounced store commits is proven and performant.
RAF-batched overlay reads/writes with element caching Adopt Splitting each frame into read phase (snapshot geometry) then write phase (apply styles) avoids layout thrashing.
Collapsible iframe frames — DOM removal, not hide Adopt Dropping the heavy iframe from the DOM entirely when collapsed, not just hiding it, saves memory and rendering cost.

Layer Inspector

Instatic ApproachRelevance to Nudge UI
Flat Record<string, PageNode> — tree emerges from children: string[] Adopt Flat storage + denormalized parentId = O(1) node lookups. Tree structure is a view, not the storage model. This is the pattern you should use.
Per-node granular subscriptions — selectedNodeIds.includes(nodeId) Adopt Each TreeNode subscribes only to its own selection state. Canvas click → only old+new rows re-render, not the entire tree.
ExpansionStore — external observable, useSyncExternalStore Adopt This prevents the "expand one row = re-render every row" problem. Expansion state should NOT be in Zustand or React context.
Three-layer DnD — gesture orchestration / geometry / pure engine Adopt Separating DnD into gesture handling (UI), geometry resolution (measure), and validation (core engine) is clean architecture. The pure engine layer makes DnD logic testable.
DnD state in refs, not React state Adopt Tracking drag state in refs + equality-guarded setTarget avoids re-rendering target rows on every pointer move.
No virtualization — relies on React.memo + granular subscriptions Evaluate Works for Instatic's scale. If your trees can be 10,000+ nodes, you may need virtualization. But their subscription model means even large rendered trees are cheap to update.
Search bypasses tree rendering — flat list when filtering Adopt Switching to a flat search results list avoids the complexity of virtualizing a recursive tree.
Shared tree primitives — TreeRow, TreeChevron, TreeIconSlot, TreeLabel Adopt Extract reusable tree row components. They're used by both the DomPanel layer tree and the Site Explorer.

Architectural Patterns Worth Borrowing

PatternWhere UsedWhy It's Good
Declarative mapping tables (not imperative logic) HTML_TO_MODULE_RULES, element→module mapping Readable, testable, extensible. Adding a new element type is one entry in the table.
Pure engine layer with no UI imports src/core/page-tree/dnd.ts, mutations.ts Business logic is testable without React. The entire import pipeline (cssToStyleRules) is a pure function.
Single source of truth — page tree in Zustand All panels subscribe, no panel keeps a local copy Enforced by Constraint #182 in their architecture tests. No drift between canvas, layers, and properties panel.
Canonical authority per concern One sanitiseCssValue.ts for all CSS sanitization. One readCssDeclarationBlock() for all CSSOM reading. No duplicated validation logic. No inconsistencies in what's allowed.
Multi-selection everywhere Layers: multi-select, multi-drag, multi-hide, multi-delete. Shift/Cmd-aware. First-class multi-selection in the selection store slice enables all panels to be multi-node aware.
External observables for volatile state ExpansionStore for tree nodes. Ref-based DnD state. Not all state belongs in Zustand. Volatile/transient UI state in external stores prevents cascade re-renders.
